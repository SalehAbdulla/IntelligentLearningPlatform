# ===========================================================================
#  commit-hygiene-allowlist.txt — commits exempt from tools/check-commits.sh
# ===========================================================================
#
# WHY THIS FILE EXISTS
#   `tools/check-commits.sh` refuses a branch whose commits are not attributable or are not
#   Conventional Commits. Some commits genuinely cannot be made to pass on their own: a subject
#   that has been pushed cannot be reworded without a force-push, which docs/12 §5 forbids.
#
#   They are named HERE, individually, rather than excused by a rule such as "only check commits
#   after <date>". A date rule would quietly exempt everything older forever; this list says
#   exactly which commits are exempt and why, and it cannot grow by accident. An entry here is a
#   recorded exception, not a silent one — the same principle as a lane exception recorded in
#   docs/TODOLIST.md.
#
#   **There are currently no entries.** The five that prompted this file were removed on
#   23 Oct 2026, because the branch they named was rewritten instead — see the note at the
#   bottom, which is kept as the record of why.
#
# WHAT THIS FILE DOES *NOT* DO
#   · It exempts the MESSAGE check only.
#   · It does not touch the identity check, which is resolved through `.mailmap` — an address
#     that resolves to a team address is attributable even when it is not the student one.
#   · It does not touch the lane check, which is judged on the branch diff rather than per
#     commit.
#
# REMOVING AN ENTRY
#   Two things make an entry moot: the branch is merged (the check is applied to the commits a
#   branch brings, not to history already on develop), or the branch is rewritten so the commit
#   no longer exists. Delete it then, in its own commit, with the reason in the message.
#
# FORMAT
#   <12-character sha>  <who>  <branch>  <why>
#
