Why none of these links carries a ?t= token
-------------------------------------------
Figma appends a `t=` share token when a link is copied from the Share dialog. It is
scoped to the copy, not to the file: three copies of this file's link, taken on
16 Oct and 17 Oct, carried three different tokens. A token is therefore not part of
the file's identity, it can be revoked, and a link that works only because of one is
not a link a marker can rely on. Every URL in this document is the plain form, which
works for anyone as soon as link sharing is set to "Can view".

That also makes these links self-checking. Open any one of them in a private browser
window: if it loads without signing in, link sharing is on; if it asks for an account,
it is off and item 1 of section 9 is still open.

5. Prototype wiring, what is actually connected
-----------------------------------------------
This was rebuilt at element level. Earlier the file held a linear "click
anywhere, go to the next screen" chain, which is not an interactive prototype.
That was removed and replaced with real hotspots.

  Prototype connections in the file : 320
  Screens with element-level hotspots : 98 of 106
    (the hotspot is attached to the actual button, tab item, list row or
     modal action that a user would tap, not to the screen background)
  Screens that are deliberately tap-anywhere : 8
    27, 28, 124  processing states, tap to continue
    46           flashcard front, the whole card is the flip target
    59           review list, tap to go back
    128          notification inbox, tap to dismiss
    138, 139     accessibility and RTL proof frames
  Named prototype flow start points : 16

Navigation model implemented:
  - a 5-item student tab bar (Home, Library, Study, Progress, Profile) that
    switches tabs and is wired on every screen that has one
  - every primary action has its own destination (Next, Continue, Generate,
    Save, Join, Pay, Submit, Approve, Publish)
  - list rows open their detail screen
  - modals have both a confirming path and a dismissal path
  - a loading to success transition per AI feature (36-37, 44-45, 53-54, 64-65)
  - an error to retry to recovery loop on 30, 41, 126 and 134
  - Smart Animate on the high-impact changes: the flashcard flip 46-47, the
    generating to result transitions, the payment processing to receipt, and
    tab switches

Click reachability: 110 of the 119 screens that existed at the 15 Oct 2026 audit are reachable by clicking alone. The
remaining 9 (24, 30, 41, 77, 78, 88, 126, 133, 134) are state, error and
secondary screens that a user reaches only in a specific situation; each one is
a named flow start point so it is directly reachable in the prototype player.
No screen is a dead end.

7. Visual language
------------------
Apple-style glassmorphism on a soft near-white canvas. Translucent white
surfaces with a background blur, a 1px hairline light border, a dual drop
shadow and an inner light edge. Palette built on the Apple system-blue family;
brand blue #0062CC was chosen over Apple's #007AFF because #007AFF measures
4.0:1 on white and `primary` is used as text in 26 places, whereas #0062CC
measures 5.80:1. A complete light and dark mode is defined, and as of 8 Oct 2026
the dark mode is also *drawn*: 130 dark variants on page 6.

Correction for accuracy, measured on 8 Oct 2026: inside each screen, the
surfaces, cards, text and decorative blobs are variable-bound (48 of 49 nodes
on a typical screen), so a token change propagates through all of them. The one
exception is the **root frame's background gradient**, which is a fixed light
gradient rather than a variable, so switching the variable mode alone would
leave light text on a light canvas. That is why each dark variant on page 6 also
gets the dark canvas gradient (bg/a #0B1220 to bg/b #10233A) applied to the
clone. An earlier revision of this document claimed that *all* fills are
variable-bound, which was not accurate at the frame level.

8. Accessibility and legibility
-------------------------------
Every text node is token-bound and contrast was measured from rendered pixels,
not estimated. Fill-only semantic colours (secondary, accent, warning) are never
used as text; text-safe variants (secondaryText, accentText, warningText) are
used instead, each clearing WCAG AA. Large-text proof is a built frame (138) and
right-to-left Arabic proof is a built frame (139).
